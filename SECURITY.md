# Безопасность PullApps

## Поддерживаемые версии

Исправления безопасности выпускаются для последней опубликованной версии и
актуальной ветки `main`.

## Как сообщить об уязвимости

Не создавайте публичный issue, если проблема может раскрыть Apple ID, токены,
cookie, содержимое Keychain или дать возможность выполнить произвольную
команду/прочитать чужой файл. Используйте **Security → Report a vulnerability**
в репозитории GitHub (Private vulnerability reporting).

В сообщении укажите версию PullApps и macOS, сценарий воспроизведения и возможное
влияние. Не прикладывайте реальные пароли, коды 2FA, DSID, cookie или IPA-файлы.

## Модель хранения данных

- Пароль и код 2FA передаются локально установленному `ipatool`; PullApps не
  записывает их в файлы и не отправляет на собственный сервер.
- Токен сессии хранится в macOS Keychain. Для переключения аккаунтов PullApps
  создаёт отдельные записи Keychain в сервисе `pullapps.accounts`.
- Cookie сессий хранятся с правами `0600` в
  `~/Library/Application Support/PullApps/accounts/`, как и cookie самого
  `ipatool` в `~/.ipatool/cookies`.
- Метаданные аккаунтов (имя, email и DSID) находятся в локальном
  `accounts.json` с правами `0600`.
- Поиск и скачивание обращаются к сервисам Apple через `ipatool`; PullApps не
  имеет собственной аналитики или телеметрии.

Защищайте локальную учётную запись macOS и не запускайте изменённые сборки из
неизвестных источников. Релиз пока не подписан Developer ID и не нотарифицирован.
